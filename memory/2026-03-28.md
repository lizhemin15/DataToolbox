# 2026-03-28 协作编排模式开发

## 任务概述
修复 AnyClaw 协作编排模式，从只显示一个节点改为自动显示所有协作人员节点。

## 关键问题与解决方案

### 问题1: 编排模式只显示一个节点
**原因**: 协作人员数据来源不明确，需要手动添加

**解决方案**:
1. 新增 `CollabTopologyPanel` 组件 - 支持拖拽/点击连线
2. 新增 `collab_roster_slugs` 字段存储协作人员快照
3. API 启动时自动从工作区 config.json 读取 agents.list
4. 打开编排模式时自动显示所有已招募实例

### 问题2: 协作人员同步机制
**三种同步方式**:
1. **容器同步** (推荐): 容器启动时调用 `POST /collab/bridge/roster/sync`
   - 需要: `ANYCLAW_API_URL`, `ANYCLAW_INSTANCE_ID`, `ANYCLAW_TOKEN`
2. **宿主机文件补全**: SSH 读取 `/var/lib/anyclaw/ws-{instance_id}/config.json`
   - 需要: 实例绑定宿主机 (host_id 非空)
3. **手动添加**: 在「协作展示名」页面手动填写

### 问题3: DNS 污染
`api.github.com` 解析到错误 IP (45.144.136.251)，导致 TLS 握手超时
- 正确 IP: 140.82.116.4
- 解决: 使用 web_fetch 访问 GitHub Actions 页面

# 2026-03-28 下午 - 跨实例协作重构

## 任务目标
将跨实例消息从独立模块融入普通对话，用户可直接说"联系XXX"让龙虾联系其他实例。

## 关键改动

### 1. peer_instances 功能
- API `GET /collab/bridge/roster` 返回 `peer_instances`（账号级拓扑邻居）
- 数据库表: `user_instance_topology_edges`
- 前端判断协作关系只用 `peer_instances`，不检查 agent 级 edges

### 2. 移除独立模块
- 删除 `InstanceCrossInstanceMailPanel` 跨实例消息面板
- 编排模式只保留拓扑配置

### 3. 龙虾工具
- `collab_get_roster`: 获取协作名单和 peer_instances
- `collab_find_peer_instance`: 按名称查找邻居实例
- `collab_send_instance_message`: 发送跨实例消息

### 4. 系统提示词
- 强调跨实例可达性**仅**由 `peer_instances` 决定
- `edges` 是同实例内员工 slug 邻接，与跨实例无关

### 5. 镜像版本显示
- API: `/api/version` 返回 manager 版本（git commit + 构建时间）
- Server: `/health` 返回 server 版本
- 前端: AdminConfig 页面显示版本信息

## 数据库状态
